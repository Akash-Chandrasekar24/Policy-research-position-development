# Karnataka & Bengaluru Impact Assessment

A national policy discussed only in the abstract is not useful to a
constituency MP. This skill grounds the question in what actually changes
for Karnataka, Bengaluru, and Bangalore South specifically.

## Checklist

Work through each dimension; state "not applicable" explicitly rather than
skipping it silently:

1. **Economic impact** — effect on Karnataka's economy or specific
   industries concentrated there (IT/ITES, biotech, aerospace).
2. **Employment impact** — jobs created, at risk, or requiring new skilling,
   specifically in Karnataka/Bengaluru.
3. **Startup ecosystem impact** — effect on Bengaluru's startup base
   (compliance burden, funding access, talent).
4. **Public-service impact** — effect on state-delivered services
   (healthcare, transport, utilities) in the constituency.
5. **Infrastructure requirements** — does this policy require or interact
   with infrastructure (metro, roads, data centres, power) relevant to
   Bangalore South?
6. **State implementation readiness** — does the Karnataka government have
   the institutional capacity to implement this, or would it need support?
7. **Constituency-specific relevance** — is there a specific Bangalore
   South angle (a facility, a demographic, a past commitment) that changes
   how this lands locally?

## Evidence to use

- The Karnataka & Bengaluru Impact Karnataka/Bangalore South knowledge base
  (economic profile, major industries, infrastructure projects, employment
  data, constituency issues, state policies, stakeholder representations).
- The `bangalore_south_tenders` and `bmrc_metro_tenders` MCP tools where
  attached, for live evidence of current public spend and infrastructure
  activity in the constituency — these are dated and citable, unlike a
  general web search.
- Web search for anything not covered by the above.

Every finding below must carry the literal source URL it came from (a
tender listing, a government notification, a news report) — the MP's
office needs to be able to click through and verify it, not just trust the
summary.

## Output format

```
Economic impact: <finding (source URL), or "not applicable">
Employment impact: <finding (source URL)>
Startup ecosystem impact: <finding (source URL)>
Public-service impact: <finding (source URL)>
Infrastructure requirements: <finding (source URL)>
State implementation readiness: <finding (source URL)>
Constituency-specific relevance: <finding (source URL)>
```

## Common failure modes to avoid

- Restating the national-level finding without actually localizing it
  ("this affects startups" instead of "this affects the ~X Bengaluru-based
  AI startups doing Y").
- Treating "not applicable" as a reason to skip the dimension entirely
  rather than stating it, which leaves the reviewer unsure whether it was
  considered.
- Reporting a finding without the URL it came from, even when one exists.
