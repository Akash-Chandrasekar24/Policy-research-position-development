# Policy Brief Writing

The office needs the same underlying analysis in different lengths and
formats for different audiences. This skill defines each format precisely
rather than leaving structure to improvisation.

## Output 1: Policy Snapshot (one page)

```
Policy issue: <one line>
Why it matters now: <2-3 sentences>
Current government position: <summary>
Three key facts: <bulleted, each with its source URL>
Main stakeholders: <short list>
Recommended position: <the [Draft position] or [Approved position], labeled correctly>
Major risk: <the single biggest one from red-teaming>
Immediate action: <what the office should do next>
Sources: <every source URL cited above, deduplicated, as a numbered list>
```

## Output 2: Detailed Policy Brief (5-10 pages)

Sections, in order: Background · Evidence · Existing policy · Stakeholder
views · Karnataka/Bengaluru impact · International comparison · Policy
options · Trade-offs · Recommended position · Implementation roadmap ·
**Sources and References**.
Pull each section directly from the corresponding upstream skill's output
— do not re-derive analysis at this stage, assemble it. Carry forward
every source URL attached to a claim in its section, and end the document
with a consolidated "Sources and References" section listing every URL
cited anywhere in the brief, deduplicated, in the order first cited.

## Output 3: Decision Matrix

Table: `Option | Benefits | Risks | Feasibility | Bengaluru impact |
Recommendation` — one row per option from `policy-option-generation`,
populated from `cost-benefit-and-tradeoff-analysis` and
`legal-and-institutional-feasibility`. Append a `Sources` footer row or
footnote list with every URL backing the figures in the table.

## Output 4: Position Note

```
Recommended position: <statement>
Core argument: <the strongest 1-2 sentence rationale, with its source URL>
Conditions: <bulleted safeguards>
Sources: <source URL(s) backing the core argument>
```

## Labeling discipline

Every one of these outputs must carry the correct label — [Draft position]
until human approval has actually happened, [Approved position] only
after. Never let the polish of a formatted document imply a status the
position hasn't earned.

## Citation discipline

Never drop a source URL when reformatting an upstream finding into one of
these outputs — a claim without its citation is not "cleaner," it's
unverifiable. If an upstream finding was marked [UNVERIFIED] or "source URL
unavailable," carry that flag forward too rather than smoothing it away.

## Common failure modes to avoid

- Introducing new analysis or softened/hardened claims that don't appear
  in the upstream skill outputs — this step formats, it doesn't re-argue.
- Writing the Policy Snapshot so vaguely that "immediate action" isn't
  actually actionable.
- Stripping source URLs out during formatting because they look untidy —
  add a Sources section instead of deleting them.
